# 跳板主机

如果一台主机的 `ProxyJump` 指向同一份配置里的另一个 `Host` 条目，它就经由 Shellder 为那个条目保持的主连接来连接。这一跳复用跳板主机的套接字，而不是另开一个用完即弃的连接，所以不管有多少台主机经由它，跳板主机只需要登录一次。

## 打开和关闭

- **打开内层主机**的开关，会把跳板主机也一并打开。先建立跳板主机的连接，再经由它连接内层主机。等待期间，内层主机的状态行显示“等待跳板主机 …”。
- **关闭内层主机**不会关闭跳板主机：它现在和其他已连接的主机没有两样。
- **关闭跳板主机**会把它后面的主机一起断开。在跳板主机上用“断开”和“关闭套接字”也是一样。
- **跳板主机连接失败**时，等它的主机也以同样的原因失败。

## 锁

锁遵循同样的规则：

- 锁定内层主机会锁定它的跳板主机；
- 解锁跳板主机会解锁它后面的主机。

## 在哪里能看到

- 跳板主机的主机页上，状态行写着哪些主机经由它连接。
- 内层主机的连接卡片在地址后面写着“经由 …”，配置卡片里的 `ProxyJump` 一行也标明它是列表里的主机。

## 多级跳转和其他情况

多级跳转（`ProxyJump` 指向的主机自己也有 `ProxyJump`）的行为相同。

不是 `Host` 条目的一跳，或者没有 `ControlPath` 的一跳，交给 ssh 自己处理。它的提问仍然由 Shellder 回答：这一跳在同一个终端上提问，先于它后面的主机，见[提示窗口](prompt-window.md)。

跳板主机之间绕成一圈的主机，会带着这个错误被关闭。
