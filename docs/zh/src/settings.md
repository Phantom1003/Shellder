# 设置

设置窗口里是应用自身的设置：怎样启动、是否留在后台、界面语言、钥匙串的访问、默认重连规则和更新。在任何窗口里按 ⌘, 都能打开它，也可以从[主窗口](main-window.md)的列表工具栏和菜单栏菜单打开。终端的设置不在这里，而在控制台自己的[设置窗口](console-settings.md)里。

## 启动

| 设置 | 作用 |
|---|---|
| “登录时启动” | 把 Shellder 加入登录项：macOS 上是 `~/Library/LaunchAgents/local.shellder.plist`，Linux 上是 `~/.config/autostart/local.shellder.desktop` |
| “静默启动” | 由登录项启动应用时不显示主窗口 |

两项默认都是关闭的，要你自己打开：在你要求之前，不会往 `~/Library/LaunchAgents` 里写任何东西。

“静默启动”只能和“登录时启动”“后台执行”一起打开（没有后者的话，既没有窗口也没有图标），关闭“后台执行”时它也随之关闭。它只管登录项的启动：双击或 `open` 总是会打开窗口。`shellder --background` 可以让单独某一次启动不显示窗口。

## 后台

| 设置 | 作用 |
|---|---|
| “后台执行” | 关闭最后一个窗口时不退出，而是离开 Dock，连接继续保持 |
| “显示在菜单栏” | 显示[菜单栏图标](main-window.md)。需要先打开“后台执行” |
| “菜单栏图标反色” | 仅 Linux：把图标变成浅色，适合深色面板。macOS 会自己给图标着色，所以那里不显示这一项 |

默认情况下，关闭最后一个窗口会退出应用并关掉它的主连接。打开“后台执行”之后，应用仍然可以通过菜单栏图标找到（点击打开主窗口，主窗口在最前面时再点一次把它收起，右键点击显示菜单），再启动一次应用也可以。

最小化到 Dock 的控制台或文件窗口仍然算是打开的：这时关闭主窗口，应用会和那个窗口一起留在 Dock 里。

退出时，应用启动的每一个 ssh 都会随之结束，包括终端的、会话的和复制的。它们都不允许作为后台主连接留下来：不管配置怎么写，这些 ssh 的 `ControlPersist` 都是关闭的，因为 macOS 26 会把留有残余进程的应用报告为仍在后台运行。

没有任何主连接时菜单栏图标是淡色的，只要有一个主连接建立就恢复正常；错误和提问不会改变图标。在 Linux 上，面板按原样显示这张深色的图，“菜单栏图标反色”就是为此准备的。

## 外观

“语言”选择界面语言。不管系统语言是什么，默认都是英文，除非你另选一种；修改之后要重新启动才生效：改过之后，菜单下面会出现“重新启动以应用”按钮。

内置英文和简体中文。日志始终是英文。

要添加一种语言：把 `ui/lang/zh-Hans.json` 复制为 `ui/lang/<lang>.json`（文件名用 BCP 47 名称，如 `ja` 或 `zh-Hant`），翻译右边的值（键是英文原文，`{name}` 是占位符），再把这种语言加到 `ui/settings.js` 开头的列表里。译文里缺少的键会回退到英文。参见[构建](build.md)。

## 钥匙串

“保险库”一行说明 Shellder 能否读取保险库：“可读取”，或者钥匙串拒绝时给出的原因。

“向钥匙串申请授权”会立刻再问一次。全部凭据都存在同一个钥匙串条目里，所以即使钥匙串没有获准打开它，也不会丢失任何东西。启动时被关掉的钥匙串询问，在五分钟之内不会自动再问。详见[钥匙串](keychain.md)。

## 重连

这个分区（界面上的标题目前是“重连策略”）里是默认规则：锁定的主机断线之后如何恢复。除非主机页上给了自定义规则，每台主机都按它来。

| 行 | 含义 |
|---|---|
| “重试间隔” | “逐次加倍”或“固定” |
| “首次等待”（固定时叫“等待”） | 第一次尝试失败之后等多久，单位是秒 |
| “最长等待” | 加倍到多少为止，单位是秒 |
| “放弃” | “从不”，或者断开多久之后放弃 |
| “自定义规则” | 有自定义规则的主机，每台一行，写着它的规则。有这样的主机时才显示 |
| “健康检查” | 多久检查一次已建立的主连接。只显示，不能在这里修改 |
| “连接超时” | 一次连接尝试最多可以花多长时间。只显示，不能在这里修改 |

初始的默认规则是：等待时间从 5 秒起逐次加倍，最长 10 分钟，永不放弃。各个字段的含义和等待时间的算法，见[开关与锁](switch-and-lock.md)。

## 文件

Shellder 用到的路径：

| 行 | 内容 |
|---|---|
| “ssh 配置” | Shellder 读取的 ssh 配置；旁边的按钮在你的编辑器里打开它 |
| “包含的文件” | 它用 `Include` 引入的文件（有的话） |
| “日志” | `shellder.log`；旁边的按钮打开它 |
| “状态目录” | 保存偏好设置、锁和日志的地方 |

登录项指向的不是正在运行的这一份应用时，这里会显示一条警告。

## 软件更新

最后一个分区显示“版本”和更新的状态。

- 打开“自动检查更新”（默认打开）时，应用在启动几秒钟之后以及此后每天一次，从 GitHub 读取最新发布版本的 `latest.json`。有新版本时，它会在这里、在主窗口的列表工具栏和菜单栏菜单里告诉你。
- “立即检查”马上检查一次。
- 在你点击“安装并重新启动”之前，不会安装任何东西。点击之后，它下载该版本适用于本平台的更新包，用应用内置的密钥校验签名，就地替换正在运行的应用，然后重新启动。“更新说明”打开该版本的页面。
- 只有版本号比正在运行的更新，才算新版本，所以版本号相同的本地构建不会被替换。

发布版本用维护者的 Apple Development 证书签名，所以从你自己签名的构建更新过去之后，第一次启动可能会出现一次钥匙串询问。详见[钥匙串](keychain.md)。
