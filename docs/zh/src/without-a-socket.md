# 没有套接字时

主连接通常拥有一个套接字（它的 `ControlPath`），其他 ssh 命令都复用它。主机没有套接字有两种原因：它的配置里没有 `ControlPath`，或者这个平台的 ssh 根本不支持 ControlMaster。这样的主机照样可以打开、锁定、重连，显示上也和其他主机一样；不同的是哪些东西能经由它的连接。

## 主连接仍然做的事

Shellder 运行同样的 ssh，只是不带 `-M`。这样连接保持着，主机配置里要求的端口转发（`LocalForward`、`RemoteForward`、`DynamicForward`）也随之保持。

没有套接字可以检查，所以 Shellder 以 ssh 自己输出的 “Authenticated to host” 作为连接已建立的标志。状态点和状态行显示“已连接（无套接字）”。

## 它做不到的事

这样的主连接不能为其他 ssh 命令、控制台窗口或文件窗口服务：它们各自登录，提问由 Shellder 回答。在工具卡片或控制台端口面板里添加的端口转发建在主连接的套接字上，所以需要主机以带套接字的方式连接。

主机页用一张[提示卡片](main-window.md)说明是哪一种情况。对没有 `ControlPath` 的主机，卡片给出需要加到 ssh 配置里、让它得到套接字的那几行。

## 文件窗口

主机没有主连接时，它的文件窗口通过一个“会话”来列目录：一个 `ssh host sh`，在窗口第一次要求列目录时登录，之后一直开着。列目录、新建和删除都由它执行。不管列多少次目录，每台主机只登录一次；Shellder 退出时会话关闭。

复制用的仍然是经由主连接时的那个 sftp（两台主机之间用 scp），只是每次复制各自登录，提问以同样的方式回答。所以一次复制要花一次登录；在使用一次性验证码的主机上，要花下一个验证码，因为刚用过的验证码不会再送一次。中断的复制可以从已经写入的部分继续，和经由主连接时一样。

## 命令行

`shellder status` 只能向带套接字的主连接询问它是否已建立。没有套接字的标为 `?`：它只由应用自己保持着。

`SHELLDER_NO_CONTROLMASTER=1` 让应用在支持 ControlMaster 的平台上，表现得像在不支持的平台上一样。
