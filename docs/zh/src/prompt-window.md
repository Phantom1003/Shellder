# 提示窗口

提示窗口是 Shellder 把提问转给你回答的地方。ssh、sudo 和 polkit 在终端上提问（密码、验证码、主机密钥确认）；Shellder 在那里读到提问，能用钥匙串回答的就自己回答。回答不了的提问出现在这个小窗口里。它浮在其他窗口之上，在 macOS 上也浮在全屏窗口之上：某个标签页登录时提问，全屏的控制台不会被切走。

## 窗口的各个部分

- **提示标题**说明要的是什么（“需要密码”“需要密钥口令”“需要验证码”“确认主机密钥”或“ssh 有问题要问”），以及是谁在问：登录时是 `ssh → 主机`；控制台里某个需要密码的操作，则是这个操作和它所在的主机（`mount /dev/sdb1`、`kill -TERM 1234`）。
- **排队计数**在提示标题的右边，说明还有几个提问在等（“还有 2 个”）。一次只显示一个提问；回答完这一个，下一个才出现。
- **提问原文**是提问方的原话，原样显示。主机密钥的提问里包含指纹。
- **回答框**是输入回答的地方。密码和口令以圆点显示；旁边的眼睛可以显示输入的内容。
- **保存选项**“保存到钥匙串，下次由 shellder 自动回答”在问密码和密钥口令时提供。勾选之后，回答会作为这台主机的凭据保存下来。为控制台操作输入的密码同样可以保存为这台主机的密码。
- **按钮**：“取消”和“继续”。输入内容之后，回车即“继续”；Esc 即“取消”。

## 提问的种类

| 种类 | 回答什么 | 能否保存 |
|---|---|---|
| 密码 | 主机上这个账户的密码 | 能 |
| 密钥口令 | 私钥的口令 | 能 |
| 验证码 | 身份验证器里的验证码。把 TOTP 密钥保存到主机页的凭据卡片之后，Shellder 会自己生成这些验证码 | 不能 |
| 主机密钥确认 | 没有回答框：“是，连接”或“不连接”（回车和 Esc）。请把指纹与服务器管理员提供的比对；回答“是”会把该密钥加入 `~/.ssh/known_hosts` | 不能 |
| 其他 | 任意文字 | 不能 |

## 提问是怎样被回答的

ssh 从不从标准输入读密码：它会打开自己的控制终端。Shellder 给每个主连接一个伪终端作为控制终端，仅此而已。标准输入、标准输出和标准错误都留在管道上，所以 ssh 的诊断信息进入日志，不会和提问混在一起。

ssh 留在这个终端上、没有换行并且以 `:` 或 `?` 结尾的文字，就是一个提问。接下来 Shellder：

1. 判断这个提问属于哪台主机。`ProxyJump` 的每一跳会打印 `user@host`，Shellder 拿它和每台主机解析后的配置比对；
2. 凭据已保存时，从钥匙串回答。TOTP 验证码是现场生成的，同一个验证码不会用两次；
3. 否则在提示窗口里显示这个提问。

`ProxyJump` 的一跳在同一个终端上提问，先于它后面的主机，它的提问带着自己的 `user@host`，Shellder 就靠这个把它区分出来。

控制台标签页的登录、文件窗口的登录和复制的登录都以同样的方式回答；控制台里需要密码的操作，sudo 或 polkit 问的问题也是如此。参见[控制台](console.md)。

## 取消

取消某台主机主连接的提问，会关闭这台主机的开关，所以猜错的密码不会反复冲击服务器。拒绝主机密钥的结果相同。

取消控制台操作的提问，这个操作就此结束。标签页、文件窗口或复制的登录被取消时，只是这一次登录失败，主机的开关不受影响。

## 密码错误

Shellder 运行 ssh 时带着 `NumberOfPasswordPrompts=1`，所以一个错误的凭据只会造成一次登录失败，主机随即关闭而不是重试。如果刚从钥匙串送出密码或口令，ssh 又问了一遍，说明服务器拒绝了它：Shellder 不会再送第二次，这次尝试到此结束。请在主机页的凭据卡片上修改这项凭据，然后重新打开主机的开关。

有些服务器在几次登录失败之后会把客户端的 IP 地址封禁一段时间。

控制台的操作有所不同：sudo 的密码不一定是登录密码，所以主机不接受已保存的密码时，提问会转到提示窗口。
